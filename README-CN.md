# AutoGraderLM

基于LLM的自动化作业评分系统，支持图形化交互界面。



## 1. 作业配置

以下内容通过UI界面的“作业配置”页面进行配置：

配置单次作业的每道题目，包含：

- 题干内容，文本或图片，通常为图片，需要支持粘贴上传。
- 题目分值（如果有多个小问则为总分值，每个小问的分值在评分标准一栏中配置），整数（0-100）
- 评分标准，通常为一段文本，作为prompt的输入的一部分，用于指导LLM进行评分
- 示例答案，可选，通常为文本或图片【即“标准答案”】，作为prompt的输入的一部分，用于指导LLM进行评分（few-shot learning, In-context learning）

完成配置之后，将配置信息保存到`./questions/{qid}/`下.

## 2. 作业解析

### 作业导入

从制定的路径下读取学生作业文件，每份作业均为一个PDF文件，通过文件名映射索引。

### 作业切分

由于每次作业包含多道题目，因此需要大模型根据前面给出的题目配置，对每份PDF文件切分成多份，每份对应一道题目。

实现：大模型读取题目配置与单份PDF作业文件，输出如下格式的region信息：

```json
{
  "questions": [
    {
      "qid": "Q1",
      "regions": [
        {"page": 1, "bbox": [0,110,1264,300]}
      ]
    },
    {
      "qid": "Q2",
      "regions": [
        {"page": 1, "bbox": [0,300,1264,520]}
      ]
    },
    {
      "qid": "Q3",
      "regions": [
        {"page": 1, "bbox": [0,520,1264,780]}
      ]
    },
    {
      "qid": "Q4",
      "regions": [
        {"page": 1, "bbox": [0,780,1264,1080]}
      ]
    },
    {
      "qid": "Q5",
      "regions": [
        {"page": 1, "bbox": [0,1080,1264,1400]},
        {"page": 2, "bbox": [0,0,1264,1635]}
      ]
    }
  ]
}
```

prompt要求：宁多勿少，尽量切分出所有题目，不要漏掉。注意分栏与跨页的情况。
这里对输出的schema进行限制，如果尝试`max_retry`次后仍然无法得到符合要求的输出，则该过该份PDF作业，在日志中记录报错。

得到切分bbox后，将PDF进行切分得到以题目为单位的作业文件（图片格式），并保存到指定路径下，路径为
`./answers/{PDF文件名}/{qid}-{page-idx}.png`

此时能够得到 (filename, qid) -> [image_1, image_2, ...]的映射关系。

## 3. 作业评分

输入：

- 该题的题目配置信息（题干、分值、评分标准、示例答案）
- 该题的作业图片（image_1, image_2, ...）

prompt设计：要求模型不要直接给出回答，而是首先解析答案，然后理解判断解题思路，最后进行评分。

输出：

```json
{
    "score": int[0-MAX_SCORE],
    "confidence": int[0-4], // 0：丢失全部作答或完全不能理解作答 1：丢失部分作答或不能理解部分作答 2：作答完整，但思路无法判断是否正确 3：作答完整，基本能够理解并判断是否正确 4：作答完整，完全能够理解并判断是否正确 
    "summary": string, // 对该作答的总结，采用什么样的思路进行作答
    "comments": string, // 对该作答的评论，特别是对于错误的地方给出具体的评语
}
```

单次作答评价完成之后应该保存如下的数据结构：

```json
{
    "filename": string,
    "qid": string,
    "answer": [
        "image_1_path.png",
        "image_2_path.png",
        ...
    ],
    "grader": string, // 评阅人：LLM 时为模型名（见 config 中 assignment_grading）；人工复核后为 "human"，前端显示「人工评阅」
    "graded_at": string | null, // 评阅时间，ISO 8601 格式（如 "2025-03-06T10:30:00Z"），旧数据可能为空
    "score": int[0-MAX_SCORE],
    "confidence": int[0-4], // 0：丢失全部作答或完全不能理解作答 1：丢失部分作答或不能理解部分作答 2：作答完整，但思路无法判断是否正确 3：作答完整，基本能够理解并判断是否正确 4：作答完整，完全能够理解并判断是否正确 
    "summary": string, // 对该作答的总结，采用什么样的思路进行作答
    "comments": string, // 对该作答的评论，特别是对于错误的地方给出具体的评语
}
```

将该文件保存到`./results/{filename.json`.

### 复核机制

对于作业结果`confidence = 2`的进行大模型重试(retry次数通过`config.yaml`进行配置)直到`confidence >= 3`或达到最大重试次数。对于`confidence = 0, 1`的作业结果，不进行重试。最终汇总`confidence <= 2`的作答，按照题目分类，在UI界面的“人工复核”页面进行人工复核（显示题目和作答），由教师给出与LLM评分相同的对应字段，更新到数据表中。

### 评阅结果

在完成评价后，支持在UI界面的“评阅结果”界面按照学生学号为索引查看该同学的该次作业的评阅结果，按照题目从上到下显示，对于每道题目显示：
1. 题目的题干内容（文本或图片）和题目分值
2. 该题的作答图片（image_1, image_2, ...）
3. 该题的评分结果：得分、评分信心、总结、评语
4. 评阅人：LLM 时为模型名；人工复核后为 "human"，界面显示「人工评阅」
5. 评阅时间：评阅完成的时间（ISO 8601 格式，本地化显示）

## 4. 统计分析

### 按照单个学生的所有题目进行汇总

以下内容可以在UI界面的“评分统计”页面以表格形式进行查看：

1. 计算该学生这次作业的总分
2. 汇总该学生每道题目的score和comments字段，形成该学生的作业评语

然后通过`config.yaml`读取打分文件，是一个xlsx文件，包含如下columns:

学生作业id	学号	姓名	提交作业状态	成绩（录入项）	评语（录入项）

其中只有“成绩（录入项）”和“评语（录入项）”需要更新，其他字段直接从打分文件中读取。
因为所有的PDF文件名都满足`{学号}_{姓名}_xxxx.pdf`的格式，因此可以通过文件名直接映射学号和姓名。
然后将总分与作业评语分别更新到两个需要更新的表项中，更新完成后，将打分文件另存为xlsx文件，保存到指定路径下。该表格即为“评分统计”页面中的表格。

### 按照单个题目的所有学生进行汇总

以下内容可以在UI界面的“答题报告”页面进行查看：

1. 统计每个题目的得分分布，绘制得分分布柱状图
2. 对于一个题目，汇总所有学生的：`summary`和`comments`字段，通过`prompts/summary.jinja`和`prompts/comments.jinja`形成prompt，包括题目配置信息，所有学生的summary字段和comments字段。要求大模型归纳同学们的解题思路和容易犯的错误，形成该题目的答题报告。
